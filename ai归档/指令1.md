一、 优化后的需求清单（AI 友好版）
要想让 AI 给出高质量的代码，需求必须具备结构化和边界感。我们可以将你的原始想法整理成一份标准的软件需求说明（PRD）：

1. 核心功能需求 (Functional Requirements)
任务管理： 支持创建、编辑、删除多个独立的备份任务（类似截图中的“挡墙”、“排水沟”）。

多源与多目的地 (Source & Destination)：

来源： 支持选择本地单/多个文件或文件夹。

目的地： 支持本地磁盘路径、外部 U 盘/硬盘，以及 WebDAV 协议（支持 URL、账号、密码/Token 配置）。

备份触发机制：

定时自动： 定期备份（每日/每周/特定时间间隔）。

手动触发： 主界面一键执行，或者右键系统托盘（System Tray）图标弹窗菜单一键执行。

压缩与加密引擎：

支持 .zip 和 .7z 格式。

支持配置压缩等级（无压缩、快速、标准、极限）。

支持设置压缩密码（AES-256 加密）。

2. 技术栈与 UI 规范 (Non-Functional Requirements)
外壳： Electron (保证跨平台能力，主攻 Windows)。

前端： Vite + React/Vue3 + Tailwind CSS (或 Shadcn/ui)，打造现代化暗黑/明亮自适应 UI。

托盘方案： 利用 Electron 的 Tray 和 Menu 模块实现完全后台化运行。

二、 驱动 AI 进行软件设计的工作流
让 AI 写大型软件最忌讳“一句完整的话丢过去让它吐出全部代码”。这会导致 AI 出现幻觉、代码残缺或上下文崩塌。推荐采用 “分层渐进式” 工作流：

[阶段 1: 架构设计] ──> [阶段 2: 核心引擎] ──> [阶段 3: 托盘与调度] ──> [阶段 4: 前端 UI] ──> [阶段 5: IPC 联调]
具体的开发5步法
阶段 1：架构与工程脚手架初始化

目标： 让 AI 帮你生成项目目录结构和环境配置文件。

关注点： package.json、vite.config.ts、Electron 的主进程入口（main.ts）与渲染进程（renderer）的分离。

阶段 2：编写核心备份引擎（Node.js 主进程）

目标： 不考虑界面，先让 AI 把“文件扫描”、“压缩加密”和“上传 WebDAV”的逻辑写通。

推荐库： archiver 或 node-7z (压缩)，webdav (NPM 官方客户端库)。

阶段 3：托盘与定时调度器 (Scheduler)

目标： 实现系统托盘的右键菜单绑定，以及基于 node-schedule 或 cron 的定时器。

阶段 4：现代化前端 UI 绘制（渲染进程）

目标： 设计任务列表、新建任务弹窗、全局设置面板。

阶段 5：IPC 桥接与端到端联调

目标： 编写 preload.js，让前端的“开始备份”按钮能够真正调用主进程的备份引擎，并接收进度条回传。

三、 如何用 CLI 精准驱动 Gemini？（Prompt 模版）
在利用 Gemini CLI 交互时，建议采用 “身份定义 + 上下文输入 + 单一任务输出” 的公式。以下是你在第一阶段可以直接复制喂给 Gemini 的 Prompt 模版：

🎯 步骤一：初始化架构时使用的 Prompt
Role: 你是一个精通 Electron 和 Node.js 的资深架构师。
Task: 我想开发一个现代化的 Windows 自动化备份软件（类似 Cobian Reflector 的现代化 Electron 版）。
Core Features:

支持本地文件/文件夹多源备份。

目的地支持本地磁盘和 WebDAV 远程云盘。

支持配置压缩格式 (zip/7z)、压缩率、密码加密。

具备系统托盘右键快捷备份和后台 Cron 定时调度功能。

Request: 请先为我设计该项目的文件目录结构（要求清晰划分主进程 main、渲染进程 renderer、预加载 preload），并给出基础的 package.json 依赖配置（请包含推荐的 WebDAV 和压缩库）。先不要写具体业务代码。

🎯 步骤二：分步索要核心代码（以备份引擎为例）
Context: 我们已经建立了标准的 Electron + Vite 项目结构。
Task: 现在请为我编写主进程中的核心备份引擎模块 backupEngine.ts。
Requirements: > 1. 实现一个 executeBackup 函数，接收参数：sourcePaths: string[], targetPath: string, options: { format: 'zip'|'7z', compressionLevel: number, password?: string }。
2. 使用 Node.js 的流（Stream）或第三方高效库，确保大文件备份时不会阻塞 Electron 主进程。
3. 请给出完整的异常处理逻辑。

四、 💡 协同小贴士
利用好 Gemini 的 Context： 如果你使用的是 Gemini CLI，可以在启动时通过脚本把你的优化版需求文档（Markdown 格式）作为 system_instruction 或初始上下文挂载进去，这样它在接下来的对话中绝不会跑调。

代码单测优先： 在让 AI 写 UI 之前，先让它为你写一个纯 CLI 运行的 test-backup.ts 脚本。确保在黑窗口里能成功把文件压缩并传到你的 WebDAV 之后，再去碰复杂的 Electron 界面，效率会提升 300%。

为了让我们能更精准地切入第一步的代码构建，你希望这款备份软件首次运行时，用户感知最明显的“核心高颜值主界面”主要用来展示：（例如：类似 Cobian 的多任务状态列表，还是一个大大的“一键保护”仪表盘）
